# 005. 추천 카드 공식 링크 선택 규칙

- 상태: Superseded by 010 (적금 링크 규칙만. 정책 링크 규칙은 유효)
- 날짜: 2026-10-26

## Context (배경)

- 추천 카드에는 사용자가 눌러 신청·확인할 공식 링크가 하나 있어야 한다. LLM이 만든 URL은 쓰지 않는다(ADR 001).
- 온통청년 정책은 신청 URL(`aplyUrlAddr`)이 서울·경기 56.8% 비어 있고, 참고 URL(`refUrlAddr1/2`)까지 모두 빈 정책은 11.9%다(`journal/2026-10-26-data-quality-report.md`).
- 금감원 적금 API에는 상품별 URL 필드가 없다. 같은 API의 `companySearch`가 금융회사 홈페이지(`homp_url`)를 주고, 매핑률은 337/337이다.

## Decision (결정)

링크는 DB 값에서 정해진 순서로 서버가 고르고, 어느 규칙을 썼는지 `url_source`로 함께 내려준다.

- **정책**: 신청 URL → 참고 URL 첫 번째 → 온통청년 정책 상세 페이지 `https://www.youthcenter.go.kr/youthPolicy/ythPlcyTotalSearch/ythPlcyDetail/{plcy_no}`
  - 상세 페이지 주소는 온통청년 검색 화면의 공유 버튼(`data-shareurl`)이 쓰는 형식이다. 상세 페이지가 경로의 정책번호(`thisplcyNo`)로 데이터를 불러오는 것을 확인했다.
- **적금**: 금융회사 홈페이지(`financial_companies.homepage_url`). 없으면 `null`.

## Alternatives (검토한 대안)

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|------|------|------|--------------------|
| 정책은 항상 온통청년 상세 페이지 | 형식이 일정, 링크 깨짐 적음 | 신청 사이트로 한 번 더 이동해야 함 | 신청 URL이 있으면 바로 연결하는 편이 행동으로 이어짐 |
| LLM이 사유와 함께 URL 생성 | 구현 단순 | 존재하지 않는 URL 생성 위험 | 환각 방지 원칙(ADR 001) 위반 |
| 적금 상품 페이지 크롤링 | 상품 단위로 정확 | 은행마다 구조가 달라 유지 비용 큼, 요청 경로 외부 의존 | MVP 범위 밖. 홈페이지로 충분 |

## Consequences (결과)

- 모든 정책 카드에 링크가 생긴다. 대표 사용자 점검(2026-10-26)에서 상세 페이지로 대체된 카드는 서울 미취업자 0/50, 서울 주거 관심 3/48건이었다.
- 상세 페이지는 신청 페이지가 아니다. 프론트는 `url_source`로 "신청하기"/"자세히 보기" 문구를 나눌 수 있다.
- 후속: 링크 유효성(HTTP 상태) 전수 점검은 11주차 일정에서 한다.

## 이력서·면접용 한 줄

"LLM이 URL을 만들지 못하게 하고, DB의 신청·참고 URL과 공식 상세 페이지를 정해진 순서로 골라 모든 추천 카드에 검증 가능한 공식 링크를 붙임"
