# 011. LLM 선정 사유: DB 카드 + LLM 문장, 템플릿 대체, 세션 캐시

- 상태: Accepted
- 날짜: 2026-11-13

## Context (배경)

- 파이프라인 4단계는 "답으로 확정한 후보마다 왜 나에게 맞는지"를 보여 줘야 한다. 지금까지는 정책 카드(링크·마감일·자격 코드)만 있었다.
- 환각 방지 원칙: 추천 URL·자격 조건·마감일은 DB 값만 쓰고, LLM 출력의 ID·URL은 서버가 검증한다.
- 1차 룰 필터는 "확실히 안 되는 정책"만 지운다(ADR 008). 소득은 사용자가 구간으로 답하고, 시군구를 모르면 일부 시군구 정책의 자격도 모른다. 남은 후보가 "맞는다"는 보장은 나이·취업 상태·혼인·학력에만 있다.
- LLM 호출은 수 초가 걸리고 실패할 수 있다. 인증 없는 공개 API라 호출마다 비용이 나간다. CI와 로컬은 OpenAI 키 없이 돈다.
- Render 무료 플랜(0.1 CPU, 기본 커넥션 풀)에서 요청이 LLM을 기다리는 동안 DB 연결을 잡으면 몇 건만 겹쳐도 풀이 바닥난다.

## Decision (결정)

- **엔드포인트**: `POST /v1/sessions/{id}/recommendations`. 답을 반영한 최종 후보 상위 5건(`RECOMMEND_LIMIT`)에 대해 `policy`(기존 `PolicyCandidate`, DB 값), `reason`(200자 이내), `check_points`(사용자가 직접 확인할 조건, 최대 3개), `reason_source`(`llm` | `template`)를 돌려준다. 없거나 만료된 세션은 404.
- **LLM은 문장만 쓴다**: 링크·마감일·자격 표시는 항상 DB 카드로 만든다. 프롬프트에는 사용자가 알려 준 조건과 정책 사실(JSON, 원문 400자 자름, URL 제거)만 넣고, 링크·신청 기간·마감일 언급을 금지한다. "서버가 확인한 자격은 나이·취업 상태·혼인·학력뿐"이라 소득·모르는 시군구는 `check_points`로 돌리라고 지시한다.
- **서버 검증**: 입력에 없는 `plcy_no`와 중복은 버린다. 사유·확인할 조건에서 URL·이메일을 정규식으로 지우고 길이를 자른다. 날짜를 언급한 사유는 템플릿으로 바꾸고, 날짜를 언급한 확인할 조건은 뺀다. 빠진 정책은 템플릿으로 채운다.
- **템플릿 대체**: 키 없음, `LlmError`(재시도 포함 전체 15초 시간 초과, 파싱 실패, 거부, 출력 잘림), 채택된 LLM 사유 0건이면 전부 템플릿 사유로 응답한다. 템플릿은 SQL이 보장하는 자격만 "맞다"고 쓴다. 지역은 시군구를 알 때만, 소득은 사용자 구간 전체가 정책 상한 안에 들 때만이다.
- **세션 캐시**: `sessions.recommendations`(JSONB)에 정책별 사유만 저장한다(링크·마감일은 저장하지 않음). 답을 다시 내면 SQL `NULL`로 비우고 `answers_revision`을 올린다. 저장은 "리비전이 읽을 때와 같고 만료 전"일 때만 하는 조건부 UPDATE다. LLM 사유가 하나라도 채택됐을 때만 저장하고, 캐시가 현재 상위 정책을 모두 덮을 때만 쓴다.
- **트랜잭션 밖 호출**: 읽기 트랜잭션(세션·후보·서술용 원문) → 연결 없이 LLM 호출 → 쓰기 트랜잭션(캐시). 라우터는 연결 대신 호출마다 짧은 트랜잭션을 여는 함수(`get_db_connector`, `engine.begin`)를 넘긴다. 캐시 저장이 실패해도 만든 사유로 응답한다.
- **요청 제한**: 10분에 IP별 10회·전체 120회(ADR 009와 같은 메모리 기반 이중 상한). 세션 쓰기 경로보다 좁게 둔다.
- **LLM 설정**: `gpt-4o-mini`, Pydantic 구조화 출력(`response_format`), 출력 토큰 상한 2,000, 재시도 1회. 성공·실패 호출 모두 모델·입출력 토큰·지연을 로그로 남긴다.

## Alternatives (검토한 대안)

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|------|------|------|--------------------|
| 템플릿 사유만 | 비용·환각 0 | 문장이 단조롭고 정책 원문의 지원 내용을 요약하지 못함 | 서비스 가치가 약함. 대체 경로로는 유지 |
| LLM이 링크·마감일까지 포함한 카드 생성 | 구현 단순 | 지어낸 링크, 원문의 지난 신청 기간을 옮겨 씀 | 환각 방지 원칙 위반 |
| 후보 전체(최대 50건) 서술 | 모든 카드에 설명 | 토큰·지연 약 10배, 출력 잘림 위험 | 결과 화면은 상위 카드 중심 |
| 정책마다 LLM 호출(5회) | 실패가 정책 단위로 격리됨 | 호출·공통 프롬프트 5배 | 한 번에 묶고 빠진 정책만 템플릿 |
| 캐시 없이 요청마다 호출 | 단순 | 새로고침마다 비용·지연 | 같은 답이면 같은 사유면 충분 |
| 요청 트랜잭션 안에서 LLM 호출 | 코드 단순 | 최대 15초 연결 점유, 무료 플랜 풀 고갈 | 읽기·쓰기 분리로 해결 |
| 별도 캐시 테이블 | 정규화 | 테이블·조인 추가, 수명은 세션과 같음 | 세션 행 JSONB로 충분 |

## Consequences (결과)

- 얻는 것:
  - 공식 링크·마감일·자격 표시는 LLM 출력과 무관하게 항상 DB 값이다.
  - LLM 장애나 키 없음에도 조회된 상위 후보 수만큼(최대 5건) 템플릿 사유로 응답한다. CI·로컬은 키 없이 같은 계약을 검증한다.
  - 같은 답이면 LLM은 세션당 한 번만 부른다. 답을 바꾸면 이전 답 기준 사유가 캐시에 남지 않는다.
- 감수하는 것:
  - LLM 사유의 사실 왜곡(예: 지원 금액을 다르게 요약)은 정규식으로 잡지 못한다. 표본 대조로 점검한다.
  - 날짜 필터가 "마감" 같은 단어가 든 정상 문장도 템플릿으로 바꾼다.
  - 템플릿 응답은 캐시하지 않으므로, LLM 장애가 이어지면 요청마다 최대 15초 기다린 뒤 템플릿을 준다.
  - 캐시 적중 요청도 요청 제한에 센다. 같은 IP를 공유하는 알파 테스트 환경에서는 IP별 10회에 걸릴 수 있다.
  - 거의 동시에 온 중복 요청은 둘 다 LLM을 부른다(데이터는 틀어지지 않고 비용만 2배).
- 후속 과제: 대표 사용자 A~D 실측(지연, 토큰, 세션당 비용, 템플릿 대체 비율, 사실 오류), 프롬프트 경량화(8주차), 역질문 LLM 문구화.

## 이력서·면접용 한 줄

"LLM 선정 사유에서 링크·마감일·자격은 DB 카드로만 만들고 LLM 출력은 ID 대조·URL 제거·템플릿 대체로 검증해, LLM 장애나 키 없음에도 환각 링크 없이 상위 후보(최대 5건)를 항상 응답하게 함"
