# 015. 선정 사유 프롬프트 경량화: 필드별 상한·중복 제거, 지연은 출력이 지배

- 상태: Accepted
- 날짜: 2026-11-24

## Context (배경)

- ADR 011은 정책 원문을 필드당 400자로 자르고 JSON으로 넣는다고 정했다. 8주차 과제는 이 입력을 줄여 비용·지연을 낮추는 것이다.
- 선정 사유는 이미 상위 5건 1회 배치 호출이고, 세션 JSONB 캐시와 일 배치 DB 미러가 있어 「캐싱 계층」은 충족한다. 남은 것은 LLM 토큰·지연이다.
- 실측 기준선(A~D 3회 중앙값, `gpt-5.4-mini`): 입력 평균 1,757토큰, 출력 474토큰, 첫 요청 LLM 지연 3,531ms, 템플릿 대체 0%.
- `policies` 3,994건 분포: 설명은 중앙값 56자로 짧고, 지원 내용만 207건이 400자를 넘는다. 추가 자격·제외 대상은 대부분 비어 있고 사유에는 확인할 조건(100자)으로만 옮겨진다. 설명·지원 내용 앞부분 중복 442건.

## Decision (결정)

- **필드별 상한**: 지원 내용 300자, 정책 설명·추가 자격·제외 대상 각 200자. ADR 011의 "원문 400자 자름"을 이것으로 대체한다(나머지 011 결정은 유지).
- **중복 제거**: 설명이 지원 내용에 포함되거나 앞 30자가 같으면 설명을 뺀다. 설명이 지원 내용을 포함하는 더 긴 글이면 남긴다.
- **빈 값 제거 확대**: 특화 대상이 없을 때 `"없음"` 대신 키를 뺀다. 나이·지역·취업·혼인·학력·소득의 `"제한 없음"`은 남긴다(정책이 제한하지 않는다는 사실이 사유 문장의 근거가 된다).
- **압축 JSON**: `separators=(",", ":")`.
- **시스템 프롬프트**: 군더더기만 정리하고 규칙(DB 사실만, URL·날짜 금지, 서버 확인 자격 4종, `check_points`)은 유지한다.
- **출력은 이번에 줄이지 않는다.** `reason` 200자·`check_points` 3×100자는 사용자에게 보이는 문구 품질이라 별도 결정으로 미룬다.
- **검증·폴백 불변**: `merge_reasons`의 plcy_no 대조·URL 제거·날짜 검사와 템플릿 폴백은 건드리지 않는다.
- **측정 재현**: `scripts/measure_reason_prompt.py`로 같은 조건의 전후를 잰다.

## Alternatives (검토한 대안)

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|------|------|------|--------------------|
| Redis 등 별도 캐시 계층 | 세션 간 사유 재사용 | 인프라 추가, 사유가 사용자 조건에 의존 | 세션 캐시·일 배치 미러로 충분 |
| `"제한 없음"` 필드도 전부 생략 | 입력 추가 감소 | LLM이 "제한 없음"을 모르는 조건으로 오해해 확인 문구로 돌릴 수 있음 | 토큰 이득이 작고 사유 품질 위험 |
| 상한을 더 낮춤(예: 지원 내용 150자) | 입력 추가 감소 | 지원 내용 207건이 400자 초과, 금액·조건이 잘려 사유 사실성 하락 | 표본 점검 없이 못 내림 |
| 출력 축소(사유·확인 조건 단축) | 지연의 주 원인에 직접 작용 | 사용자 노출 문구 품질과 맞바꿈 | 별도 결정으로 분리 |
| 정책 수 축소(5→3) | 입력·출력 모두 감소 | 첫 화면 카드 수 계약 변경(FE) | 9주차 FE 연동 뒤 판단 |

## Consequences (결과)

- 얻는 것:
  - 입력 토큰 1,757 → 1,573(-10.5%), 프롬프트 2,597 → 2,350자(-9.5%). 템플릿 대체 0/20 유지, 테스트 375건 통과.
  - 필드 집합·상한·중복 제거·압축을 단위 테스트로 고정.
- 감수하는 것:
  - **지연은 줄지 않았다**(3,531 → 3,891ms, 편차 범위). 출력 약 490토큰이 지연을 지배하고 입력 -10%는 호출 간 편차(3.4~4.3초)보다 작다.
  - 절감 비용은 세션당 약 $0.00003로 금액상 의미가 작다.
  - 상한을 낮췄으므로 긴 지원 내용(300자 초과, 후보의 약 5%)에서 사유가 일부 내용을 못 쓸 수 있다. 사실 오류 표본 재점검은 알파 테스트 전에 한다.
- 후속 과제: 지연을 줄이려면 출력 길이·확인 조건 개수·카드 수를 줄이는 새 ADR이 필요하다. 근거 수치는 `journal/2026-11-24-prompt-slimming.md`.
