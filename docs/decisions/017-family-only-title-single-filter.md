# 017. 미혼 답변 시 가구 전용 제목 정책 제외

- 상태: Accepted
- 날짜: 2026-11-28

## Context (배경)

- 「서울 사는 자취생 지원금」에서 역질문에 미혼을 답했는데 "신생아 특례 구입·전세대출"이 추천됐다.
- DB 실측: 이 정책의 `marriage_code`는 `0055003`(제한없음)이고 나이·취업·학력도 제한없음이다. 출산 가구 조건은 설명 텍스트에만 있어 정형 필터가 거를 수 없다.
- 혼인 코드 분포: 제한없음 3,884 / 기혼 70 / 미혼 38 / NULL 2. 제한없음 중 제목에 신생아·출산·신혼·임신·육아 등이 든 정책이 약 90건이다. 본문·추가 자격 키워드는 노이즈가 커서(포괄 정책의 "출산 지원 포함" 문구) 제목만 본다.

## Decision (결정)

- 미혼 답변이고 `marriage_code`가 미혼(`0055002`)이 아니면, 제목이 `FAMILY_ONLY_NAME`(신생아|출산|신혼|임산부|임신|산모|다자녀|육아|영유아|양육|난임|부부)에 걸리고 `FAMILY_EXEMPT_NAME`에 걸리지 않을 때 후보에서 지운다.
- 면제(미혼도 대상일 수 있음): 예비, 한부모, 청년과 신혼부부가 **병기**된 제목("신혼부부·청년", "청년, 신혼부부", "신혼부부 및 청년").
  - 처음에는 "청년"이 있으면 무조건 면제했으나 리뷰와 DB 확인에서 잘못으로 드러났다. "청년 신혼부부 월세", "청년부부 결혼축하금", "청년 1인 소상공인 출산급여"처럼 청년이 기혼·출산 가구를 꾸미는 제목이 43건 중 상당수였다. 지금은 병기 패턴만 면제한다.
- SQL 필터(`_policy_filters`, Postgres `~`)와 역질문 답 재필터(`question_engine._keeps_marriage`, 파이썬 `re`)가 같은 정규식 문자열을 쓴다. 로컬 DB 전체(혼인 코드가 미혼이 아닌 정책)에서 두 구현이 같은 118건을 골랐다.

## Consequences (결과)

- 로컬 DB 실측: 제외 118건, 눈으로 훑은 범위에서 오탐은 없었다(산후조리·임산부·다자녀·신혼 전용 등).
- 제목 키워드 휴리스틱이라 제목에 드러나지 않는 가구 전용 정책은 남는다. 그 경우는 선정 사유의 "확인 필요"에 의존한다.
- 공식 `제한없음` 코드를 제목으로 덮어쓰므로, 미혼 특별공급 트랙이 있는 다자녀 정책 등은 미혼에게 보이지 않을 수 있다. 제외 대신 순위 강등은 후속 검토.
- 정규식 문법을 바꿀 때는 Postgres와 파이썬 양쪽에서 동작하는지 확인해야 한다.
- 기혼 답변과 혼인 미답변에는 영향이 없다.
