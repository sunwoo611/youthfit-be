# 2026-10-17 공공 API 구조 확인과 온통청년 코드표 출처 찾기

## 상황 / 증상

온통청년·금감원 응답을 DB 컬럼으로 정규화하려면 엔드포인트, 응답 구조, 코드 값의 의미를 알아야 했다. 문서만으로는 다음이 불분명했다.

- 온통청년 엔드포인트가 두 가지로 안내됨 (`opi/youthPlcyList.do` vs `go/ythip/getPlcy`).
- 혼인·소득·취업상태·학력·전공·특화 필드가 `0013003` 같은 코드로만 오는데, Open API 문서에는 코드 값 목록이 없음.
- 금감원 적금 응답에 상품 공식 URL이 없음.

## 원인 분석

- **엔드포인트 혼선**: 공식 문서 페이지의 정적 예시는 구 API(`opi/youthPlcyList.do`, `openApiVlak`, `pageIndex`/`display`)이다. 하지만 페이지 스크립트가 실제로 안내하는 현행 API는 `go/ythip/getPlcy`(`apiKeyNm`, `pageNum`/`pageSize`, `rtnType=json`)이다. 발급받은 키로 현행 API 응답을 확인했다(총 3,264건).
- **코드표 부재**: Open API 문서(`oaiDoc`)는 JavaScript로 채워지는 페이지다. 문서 데이터(`/sur/link/openApiIntro/86`)에는 필드명의 의미만 있고 코드 값은 없다. 스크립트에는 `go/ythip/getPolicyCode` API가 보이지만 공개 문서 목록에는 빠져 있다.
- **코드표 확보**: 온통청년 정책 검색 화면(`youthPolicy/ythPlcyTotalSearch`)의 필터 HTML과 화면 표시 로직에 API와 같은 코드가 라벨과 함께 있었다.

## 해결

- 코드표를 `app/ingest/codes.py` 상수로 옮김. "제한없음"은 취업상태·학력·특화 `…010`, 전공 `0011009`, 혼인 `0055003`, 소득 무관 `0043001`.
- 샘플 정책 2건(`…113966`, `…113965`)의 공식 상세 페이지 표시와 코드 해석을 사람이 대조해 일치함을 확인.
- 연령 플래그 반전도 `…113966`(원문 19~34세, 플래그 `Y`)의 상세 페이지 연령 칸이 "제한없음"으로 표시되는 것으로 확인.
- 정규화 시 코드표에 없는 코드를 `find_unknown_codes`로 집계해, 코드 변경이나 누락을 적재 때 숫자로 감지하도록 함.

## 예상 밖 사실 (정규화 규칙에 반영)

| 항목 | 내용 | 처리 |
|---|---|---|
| 연령 제한 플래그 | `sprtTrgtAgeLmtYn='Y'`가 **제한없음**이다 (필드명과 반대). 공식 화면은 Y면 나이 값이 있어도 "제한없음"으로 표시 | Y면 `age_limited=False`, 나이는 None |
| 전국 정책 | 별도 플래그 없이 `zipCd`에 시군구 코드 전체(화면 기준 256개)가 들어옴 | 시도 배열 파생, 전국 여부는 개수로 판단 가능 |
| 소득 `0043003` | 화면에서 이름 없이 `earnEtcCn` 자유 텍스트로 표시 | "기타"로 정의, 필터에서는 판단 불가 |
| 공백 날짜 | 날짜 필드에 공백 8칸(`"        "`) | None |
| 특화 필드명 | 문서는 `sBizCd`, 실제 응답은 `sbizCd` | 실제 응답 기준, 문서 표기도 폴백 |
| 신청기간 | `aplyYmd`가 `"20260518 ~ 20260630"` 문자열. 상시(`0057002`)면 빈 값 | 구간 파싱, 여러 구간이면 최소 시작·최대 종료 |
| 금감원 URL | 적금 상품에 URL 필드 없음 | `companySearch`의 금융회사 홈페이지(`homp_url`) 사용 (ADR 003 예정) |

## 배운 점 / 재발 방지

- 공공 API 문서가 불완전하면 같은 기관의 공식 화면(필터 값, 표시 로직)이 가장 신뢰할 만한 2차 출처다.
- 필드명만 보고 의미를 추정하지 않는다. 연령 플래그처럼 반대 의미인 경우가 있으므로 공식 화면과 대조한다.
- 키가 필요한 `getPolicyCode`로 최종 확인하는 작업은 남아 있다.
