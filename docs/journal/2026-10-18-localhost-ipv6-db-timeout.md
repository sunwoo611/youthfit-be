# 2026-10-18 Windows 에서 localhost 로 DB 접속 시 2초 타임아웃

## 상황 / 증상

DB 컨테이너가 healthy 인데 스키마 비교 테스트(`test_migration_matches_models`)가 항상 "DB 연결 불가"로 skip 됐다. 같은 URL 로 타임아웃 5초를 주면 접속은 성공했다.

## 원인 분석

- 가설 1: `.env` 비밀번호·DB 이름 불일치 → 타임아웃 5초로는 접속되고 `alembic_version` 도 조회돼 기각.
- 가설 2: `localhost` 해석 순서 → 확인. Windows 는 `localhost` 를 IPv6 `::1` 부터 시도한다. 그런데 직전 커밋(`80b0ceb`)에서 compose 포트를 `127.0.0.1:5432` 에만 바인딩해 `::1` 시도가 응답 없이 대기하다 asyncpg 타임아웃(테스트·`/health` 모두 2초)을 다 써버린다.

## 해결

- `.env.example` 의 `DATABASE_URL` 호스트를 `127.0.0.1` 로 변경 (팀원 각자 `.env` 도 수정 필요).
- 포트 바인딩은 보안상 `127.0.0.1` 유지 (외부 노출 방지가 목적이었으므로 되돌리지 않음).

## 결과 (수치)

| 호스트 | 타임아웃 2초 기준 결과 | 접속 시간 |
|---|---|---|
| `localhost` | TimeoutError | 1,999ms |
| `127.0.0.1` | 성공 | 22ms |

수정 후 DB 통합 테스트(스키마 비교 + 적재 계층 3건)가 skip 없이 통과.

## 배운 점 / 재발 방지

- 포트를 루프백 IPv4 에만 바인딩하면 접속 URL 도 `127.0.0.1` 로 명시한다.
- "연결 불가로 skip" 은 실패처럼 보이지 않아 오래 묻힐 수 있다. skip 사유를 `pytest -rs` 로 주기적으로 확인한다.
