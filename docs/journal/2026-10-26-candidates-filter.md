# 2026-10-26 1차 룰 필터 API와 대표 사용자 점검

## 상황 / 증상

`POST /v1/candidates`(정책 최대 50건, 적금 최대 20건)를 만들고, 실제 적재본(정책 3,602건, 적금 337건)으로 대표 사용자 4명의 상위 후보를 뽑았다. 계획 단계의 우려는 "신청기간 확인 필요 정책이 상위를 차지하는가"였다.

## 원인 분석

- 확인 필요 정책은 상위를 차지하지 않았다. 대신 다른 문제가 나왔다. 경기 29세 재직자의 상위 50건이 모두 지역 특화 정책이었고, 그중 33건(시군구 1개 22건, 2~19개 11건)이 평택·여주·군포 등 일부 시군 주민만 대상이었다. 입력에 시군구가 없으니 사용자가 받을 수 있는지 알 수 없다.
- 서울·경기는 시도 전체 정책이 시군구 25개·44~47개를 모두 포함하고, 일부 시군 정책은 대부분 1~14개라 비율로 가를 수 있었다.
- 구현 중 확인한 데이터 사실:
  - 시도 코드 `12`가 전남광주통합특별시다. 광주(29)·전남(46) 코드는 적재본에 없다.
  - 대분류가 2025년 체계와 2026년 체계로 섞여 있고, 구분점은 반각 가운뎃점(U+FF65)이다. 관심분야 매핑에 두 체계를 모두 넣었다.
  - 중복 등록: 서울·경기 마감 제외 후보에서 이름이 같은 묶음 9개, 띄어쓰기·괄호만 다른 묶음 5개. 연도까지 지워도 추가로 잡히는 묶음은 0개였다.
  - 온통청년 상세 페이지 주소는 검색 화면 공유 버튼 형식(`/youthPolicy/ythPlcyTotalSearch/ythPlcyDetail/{plcyNo}`)이고, 상세 페이지가 경로의 정책번호로 데이터를 불러온다.

## 해결

- 정렬을 "시도 전체 > 전국 > 일부 시군구"로 바꿨다(ADR 006). 시도 전체는 그 시도 시군구의 80% 이상 포함. 시도 시군구 수는 처음에 전체 정책 `unnest` 집계(약 51ms)로 구했다가, 단일 시도 정책의 최대 시군구 수가 16개 시도 모두 같은 값을 1.4ms에 준다는 것을 확인하고 바꿨다.
- 일부 시군구 정책은 빼지 않고 카드에 `region_scope=sigungu`와 시군구 코드를 내려 역질문에서 쓸 수 있게 했다.
- 신청 가능 여부는 `policy_availability`와 같은 규칙을 SQL `CASE`로 걸고, 신청기간 구분 4종 × 날짜 4필드 × 값 4종 = 1,024개 조합에서 결과가 같음을 테스트로 묶었다.
- 공식 링크는 신청 URL → 참고 URL → 온통청년 상세 페이지 순이다(ADR 005).
- 테스트용 DB fixture를 `tests/conftest.py`로 옮겨 품질 리포트 테스트와 공유한다.

## 결과 (수치)

기준일 2026-10-26, 로컬 uvicorn 단일 프로세스, 같은 요청 6회 중 첫 회를 뺀 5회 중앙값(HTTP 포함).

| 사용자 | 정책 후보(중복 제거 후) | 상위 50 상태 | 상위 50 지역 범위 | 상위 50 링크 | 응답 |
|---|---:|---|---|---|---:|
| A 서울 25세 미취업 | 366 | 가능 50 | 시도 26, 전국 24 | 신청 36, 참고 14 | 38ms |
| B 경기 29세 재직 | 369 | 가능 50 | 시도 17, 전국 33 | 신청 23, 참고 27 | 59ms |
| C 서울 27세 주거 | 48 | 가능 37, 예정 3, 확인 필요 8 | 시도 6, 전국 42 | 신청 14, 참고 31, 상세 3 | 56ms |
| D 질의만 "경기 사는 31살 직장인인데 월세 지원 받고 싶어요" | 46 | 가능 38, 예정 1, 확인 필요 7 | 시도 1, 전국 41, 일부 시군 4 | 신청 10, 참고 33, 상세 3 | 63ms |

- B의 일부 시군 정책: 정렬 변경 전 상위 50 중 33건 → 변경 후 0건. 응답은 34 → 59ms(시도 시군구 수 서브쿼리).
- D는 질의에서 나이·시도·취업상태·관심분야 4개를 모두 규칙 사전으로 추출했다.
- 확인 필요 정책은 후보가 50건 미만인 C·D에서만 나왔고 40위 이후에 있다. C의 8건은 2025년 수정 5건, 2026년 수정 3건이다. 상위를 차지하지 않아 "올해 미수정 레코드 후순위" 규칙은 추가하지 않았다.
- 적금: 네 사용자 모두 상위 20건에 청년 상품 8건 전부가 먼저 오고, 나머지는 최고 우대금리 순이다.
- 테스트 201건 통과(DB 통합 테스트 포함).

## 배운 점 / 재발 방지

- 계획한 정렬 규칙도 실제 사용자 조건으로 뽑아 봐야 한다. "지역 특화 우선"은 시군구를 모를 때 자격 불확실한 후보를 올렸다.
- 같은 값을 구하는 더 싼 쿼리가 있는지 데이터로 확인한다. `unnest` 집계와 단일 시도 최대값이 같은 결과를 주는 것을 16개 시도 전체로 비교한 뒤 바꿨다.
- 확인 필요 정책 중 "주거포털 마이홈 개선", "도심융합특구 조성"처럼 개인 혜택이 아닌 인프라 사업이 섞인다. 룰로 거르기 어려워 3차(LLM 선정 사유 단계)에서 다룬다.
