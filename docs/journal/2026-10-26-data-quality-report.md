# 2026-10-26 적재 데이터 필드 채움률과 크롤링 필요성

## 상황 / 증상

프론트 담당이 온통청년 API만으로는 안내가 부족해 정책 URL 크롤링이 필요할 것 같다고 했다. 샘플 3건은 신청 URL이 3/3 비어 있고, 신청·심사·서류가 "별도 문의"인 경우가 많았다. 샘플로 수집 방식을 바꾸기 전에, 적재된 전체 데이터로 채움률을 재려 했다.

## 원인 분석

- 샘플 3건은 신청 URL(`apply_url`)만 봤고, 참고 URL(`ref_urls`)은 보지 않았다.
- 전국 정책은 별도 플래그가 없다. 시군구 수 분포는 단일 시도(최대 47개)와 전국(209~256개, 그중 681/694건이 240개 이상) 사이에 49~199개가 4건뿐이라, 시군구 200개 이상을 지역 무관으로 뒀다.
- 지역 무관 694건은 모두 시도 코드 11 또는 41을 포함한다. 서울·경기 960건 = 지역 한정 266건 + 지역 무관 694건이다. 두 열은 분할이 아니라 서로 겹친다.
- 신청 종료일이 없는 비율을 파서 실패로 보면 안 된다. 특정 기간(`0057001`) 1,753건 중 종료일이 없는 것은 1건이다. 상시(`0057002`) 906건과 미지정(`0057003`) 943건은 원문에 종료일이 없다.

## 해결

읽기 전용 CLI `uv run python -m app.ingest.report`를 추가했다. 집계와 판단은 DB 없이 테스트하고, 조회 경로는 트랜잭션을 롤백하는 통합 테스트로 확인했다.

판단은 서울·경기 열만 본다. 아래를 모두 만족할 때만 참고 URL 선별 보완(ADR)을 검토한다.

- URL이 하나도 없는 비율이 50% 이상
- 신청 방법·심사 방법·제출 서류 중 2개 이상이 별도 문의 또는 빈 값 비율 50% 이상

하나라도 낮으면 크롤링 없이 API 데이터로 진행한다.

```markdown
## 크롤링 필요성

판단은 서울·경기 열만 본다.

- URL이 하나도 없는 비율이 50% 이상이고
- 신청 방법·심사 방법·제출 서류 중 2개 이상이 별도 문의·빈 값 비율 50% 이상

이면 서울·경기 핵심 정책의 참고 URL 선별 보완을 검토한다. 하나라도 낮으면 크롤링 없이 API 데이터로 진행한다. 서울·경기 정책이 0건이면 판단하지 않는다.

결론: 서울·경기 960건 중 URL이 하나도 없는 비율은 11.9% (114/960)이다. 핵심 안내는 신청 방법 41.9% (402/960), 심사 방법 68.8% (660/960), 제출 서류 69.8% (670/960). URL 부재와 핵심 안내 빈약이 동시에 기준(50%)을 넘지 않아 크롤링 없이 API 데이터로 진행한다.
```

**판단: 크롤링 없이 API 데이터로 진행한다.** 선별 보완 ADR은 쓰지 않는다.

서울·경기에서 심사 방법 68.8%, 제출 서류 69.8%는 기준을 넘는다. 다만 URL이 하나도 없는 정책은 11.9%라 두 조건이 함께 성립하지 않는다. 신청 URL만 보면 56.8%가 비어 있지만, 참고 URL이 있는 정책이 많아 링크가 전혀 없는 경우는 적다. 카드의 공식 링크는 DB의 참고 URL을 쓰면 된다.

## 배운 점 / 재발 방지

- 신청 URL 공백 3건으로 크롤링을 결정하면 안 된다. 참고 URL까지 포함한 "URL 하나도 없음"은 11.9%였다.
- 나이 제한 없음은 서울·경기 45.2%라 나이 필터가 후보를 가른다. 소득 무관 86.2%, 취업상태 제한없음 75.1%는 변별력이 약하다.
- 지원 내용이 30자 미만인 서울·경기 정책은 5.7%다. 지원 내용 텍스트는 짧은 편이 아니다.
- 서울·경기 정책의 39.3%는 기준일 이전에 신청이 끝났다. 추천 후보에서는 빼야 한다.
- 오래된 적재본으로 잰 수치는 적재 시점을 함께 적는다. 다시 적재해 비교하면 결론의 안정성도 확인할 수 있다.
