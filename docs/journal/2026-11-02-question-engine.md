# 2026-11-02 역질문 세션 엔진 (LLM 없는 E2E)

## 상황 / 증상

역질문은 "후보를 가르는 자격 변수"를 서버가 골라 묻는다. 어떤 변수를 질문 후보로 둘지, 각 코드가 실제로 "해당자만 신청 가능"을 뜻하는지 정하기 위해 대표 사용자 A~D(`2026-10-26-candidates-filter.md`)의 후보에서 혼인·학력·특화·전공·소득·시군구 분포를 읽기 전용으로 쟀다.

- 기준일 2026-11-02, 적재본 2026-10-26(정책 3,602건). `policy_query`를 SQL로 컴파일해 읽기 전용 트랜잭션에서 실행했다.
- 후보 수: A 363, B 368, C 48, D 46 (10-26 대비 A·B는 마감으로 3건·1건 감소).

## 원인 분석

### 코드 의미 확인 (원문 대조)

- **"제한없음" 코드는 다른 코드와 함께 오지 않는다.** 혼인·학력·전공·특화·취업 모두 0건. 그래서 "코드 없음 또는 제한없음이면 통과, 아니면 겹칠 때 통과" 규칙을 그대로 쓸 수 있다.
- **"기타" 코드는 제한으로 볼 수 없다.** 학력 기타(0049009)는 105건(기타만 61건)에 붙어 있고 국민내일배움카드처럼 학력 제한이 없는 정책도 포함한다. 특화 기타(0014009)는 제한 정책 446건 중 188건(기타만 160건)이고 제대군인·가족돌봄청년·보훈대상·학자금 소득 조건 등 서로 다른 조건을 묶는다. 사용자가 스스로 "기타"에 해당하는지 답할 수 없다.
- **비기타 코드를 전부 나열하면 실질적으로 제한 없음이다.** 전공 8개 계열 전부 나열 24건, 학력 비기타 8개 전부 5건.
- **특화 코드는 "해당자만"과 "우대"가 섞여 있다.** 표본 20건 중 해당자만으로 읽히는 것은 군장병·장애인·여성(임산부)·중소기업 재직(내일채움공제 등)이었다. 반면 제주 재형저축(중소기업은 납입 지원금이 더 많을 뿐), 청년창업가 입주공간(원문 "해당없음"), 청년기업 디자인 지원(중소기업 코드인데 원문은 청년농업인)처럼 하드 필터로 쓰면 잘못 지울 정책이 4건 있었다.
- **혼인 코드는 의미가 분명하다.** 기혼 58건(신혼부부 대출·출산), 미혼 31건(청년주택 공급·주거안정장학금), NULL 2건.
- **소득 범위(0043002)는 46건뿐이고 단위가 섞여 있다.** 대부분 연소득 만원 단위(중앙값 5,000)지만 원 단위(43,056,240), 월소득으로 보이는 값(534, 공공분양), 의미 없는 0~0, 9999가 섞여 있다. 하한(`earn_min`)은 하한이 아니라 다른 집단의 기준인 경우가 있다(세종 "대학생·취준생 4,500만원, 부모 합산..." → 4500~7000). 상한은 "부부합산"이나 "본인+부모" 기준도 있다. 소득 기타(0043003) 442건은 자유 텍스트다(중위소득 192, 금액 55, 수급·차상위 17, 도시근로자 15 등).
- **시군구 코드.** 서울 25개는 표준 법정 시군구 코드다. 경기 48개는 31개 시군을 구 단위로 나눈 코드다(수원 4, 성남 3, 안양 2, 부천 3(2024 구 부활), 안산 2, 고양 3, 용인 3, 화성은 시 코드 41590과 2026년 신설 4개 구 41591~41597이 함께 있음). 시도 12(전남광주통합)는 새 체계 27개(12110~12870)라 기존 광주·전남 이름표와 대응을 확인할 수 없다.

### 상위 50 기준 분포와 기대 제거율

규칙: 위 "기타"·전부 나열은 제한 없음, 선택지 균등 가정. 소득은 `earn_max`가 1,000~20,000(만원)인 범위 정책만, 사용자 소득 구간 하한이 상한 이상이면 제거.

| 변수 | A 제한/50 (점수) | B | C (48) | D (46) |
|---|---|---|---|---|
| 혼인 | 1 (0.010) | 0 | 5 (0.052) | 3 (0.033) |
| 학력 | 11 (0.172) | 12 (0.190) | 3 (0.049) | 3 (0.052) |
| 특화 | 2 (0.036) | 3 (0.049) | 0 | 0 |
| 전공 | 4 (0.069) | 4 (0.069) | 0 | 0 |
| 소득 범위 | 0 | 1 (0.010) | 8 (0.052) | 8 (0.054) |
| 시군구 | 0 | 0 | 0 | 4 (0.084) |

- 학력 제한은 대학 재학(0049005) 단독이 가장 많다(대학생 천원의 아침밥, 특성화대학 등).
- 전공 제한 4건 중 3건(예비예술인, 기술경영 전문인력, 지식재산 인재)은 학력 제한(대학 재학·졸업)도 함께 걸려 있다. 학력 제한이 없는 것은 1건(매장유산 미정리유물, 인문계열)이다.
- 특화 제한은 A 군장병 2건, B 중소기업·지역인재 2건과 군장병 1건이다.
- 상위 50만 보면 사용자당 점수 > 0 변수가 2~4개다. 특화·전공을 빼면 A(학력·혼인)와 B(학력·소득)는 2개뿐이다.

### 시군구는 상위 50에 거의 없다

전체 후보에서 일부 시군구 정책은 A 7, B 38, D 4건인데 상위 50에는 D 4건만 있다. 정렬이 "시도 전체 > 전국 > 일부 시군구"(ADR 006)라 B의 38건이 모두 50위 밖이다. 상위 50만 보고 변수를 고르면 B에게 시군구를 묻지 않게 된다.

전체 후보 기준 점수(제한 건수): A 학력 0.164(79), 시군구 0.017(7), 소득 0.012(12), 혼인 0.007(5) / B 학력 0.159(77), 시군구 0.099(38), 소득 0.012(12), 혼인 0.005(4).

## 해결

질문 변수와 필터 의미를 아래처럼 확정했다(구현은 2단계).

| 변수 | 질문 | 선택지 | 필터 의미 | 비고 |
|---|---|---|---|---|
| 혼인 `marriage` | 단일 | 기혼·미혼 | 정책 코드가 기혼/미혼이면 같을 때만 통과. NULL·제한없음 통과 | 포함 |
| 학력 `school` | 단일 | 비기타 8개(고졸 미만~석·박사) | 기타·제한없음 포함, 비기타 8개 전부 나열, 빈 값은 통과. 아니면 겹칠 때 통과 | 포함 |
| 소득 `income_bucket` | 단일 | 본인 연소득 3,000만원 이하 / ~5,000 / ~7,000 / 7,000 초과 | `earn_cond_code=0043002`이고 `earn_max`가 1,000~20,000일 때만, 구간 하한 ≥ `earn_max`면 제거. `earn_min`·소득 기타 텍스트는 쓰지 않음 | 포함. 본인 소득 ≤ 가구 소득이므로 가구 기준 상한에도 보수적 |
| 시군구 `sigungu_code` | 단일 | 시도별 이름표. 경기는 시 단위로 묶고 구 코드 목록과 겹치면 통과 | `region_scope=sigungu` 정책만 사용자 시군구 포함 여부로 거름 | 포함. 시도 12와 이름표 없는 시도는 질문 생략 |
| 특화 `special` | — | — | — | 제외. 해당자만·우대 혼재, 기타 42%, 상위 50 제한 ≤3건. 선정 사유 단계에서 표시 |
| 전공 `major` | — | — | — | 제외. 상위 50 제한 ≤4건 중 3건이 학력과 중복, 대학생에게만 의미 |

공통 원칙: 질문 답으로는 **확실히 맞지 않는 정책만** 지운다. 애매한 코드(기타, 단위 이상 소득값)는 남기고 3차 LLM 선정 사유에서 "확인 필요"로 다룬다.

2단계 구현 시 반영할 것(계획과 다른 점, 2026-11-02 확정):

- 변수 점수는 상위 50이 아니라 **전체 후보**(최대 약 370건)로 계산한다. 그래야 B에게 시군구를 묻는다. 위 4개 변수와 "제한 건수 ≥ 3, 기대 제거율 ≥ 0.01" 기준이면 A 3개(학력·시군구·소득), B 3개(학력·시군구·소득), C 3개(혼인·학력·소득), D 4개가 된다.
- 시군구를 답하면 그 시군구를 포함하는 일부 시군구 정책은 **시도 전체와 같은 순위**(마감일 순으로 섞임)로 올리고, 포함하지 않는 일부 시군구 정책은 뺀다. 지금 정렬대로면 걸러도 상위 50이 바뀌지 않는다(B가 평택이면 평택 정책 14건이 331위 이하에 그대로 남음). 시군구를 모를 때 정렬은 그대로다.

## 결과 (수치)

- 측정: 정책 3,602건, 대표 사용자 4명, 상위 50 194건·전체 후보 825건.
- 질문 변수 6개 후보 → 4개 확정(혼인·학력·소득·시군구), 2개 제외(특화·전공).
- 테스트 260건 통과(DB 통합 포함), `ruff check` 통과.

### 대표 사용자 점검 (2026-11-03)

기준일 2026-11-03, 적재본 2026-10-26. 로컬 uvicorn 단일 프로세스, 6회 중 첫 회를 뺀 5회 중앙값(HTTP 포함). A~C는 필드를 직접 주고 `query`는 추출되는 단어가 없는 문장("청년 정책 추천해 주세요")을 썼다. 답은 대졸·미혼, 시군구 A·C 관악구 / B 평택시 / D 수원시, 소득 A·C 3,000만원 이하 / B·D 5,000만원 이하.

| 사용자 | 1차 후보 | 질문 순서 (affected) | 전부 답한 뒤 |
|---|---:|---|---:|
| A 서울 25세 미취업 | 362 | 학력 79, 시군구 7, 소득 10 | 306 |
| B 경기 29세 재직 | 368 | 학력 77, 시군구 38, 소득 10 | 295 |
| C 서울 27세 주거 | 48 | 혼인 5, 소득 6, 학력 3 | 44 |
| D 질의만 (경기 31세 직장인 월세) | 46 | 시군구 4, 소득 6, 학력 3, 혼인 3 | 39 |

| 사용자 | 세션 생성 | 답변 반영 | 세션 조회 | `POST /v1/candidates` (비교) |
|---|---:|---:|---:|---:|
| A | 90ms | 67ms | 62ms | 52ms |
| B | 85ms | 68ms | 58ms | 51ms |
| C | 36ms | 44ms | 37ms | 32ms |
| D | 41ms | 36ms | 31ms | 29ms |

- 질문 변수와 개수가 위 2단계 예상과 같다(A·B 3개, C 3개, D 4개). 순서는 affected가 아니라 기대 제거율 순이라 C는 선택지 2개인 혼인(5건)이 소득(6건)보다 먼저 온다.
- 시군구 답이 정렬까지 바꾼다. B가 평택시로 답하면 전체 368 → 344건, 상위 50에 일부 시군 정책 14건이 들어온다(답 전 0건). A 관악구는 362 → 356건, 상위 50에 1건. D 수원시는 일부 시군 정책 4건이 모두 빠진다(46 → 42).
- 학력 대졸 답은 A 362 → 312, B 368 → 318, C 48 → 45, D 46 → 43. 선택지별 남는 후보는 A 284~336, B 292~342건이다.
- 소득은 낮은 구간으로 답하면 지우는 정책이 0건이다(구간 하한이 상한 이상일 때만 지우는 설계대로). 7,000만원 초과로 답하면 A 352, B 358, C 42, D 40건이 남는다.
- 세션 생성은 A·B에서 후보 API보다 약 35ms 더 걸린다. 질문 점수를 상위 50이 아니라 전체 후보(약 370건)로 계산하려고 행을 끝까지 읽고 INSERT까지 하기 때문이다. 후보가 적은 C·D는 4~9ms 차이다. 모든 호출이 100ms 미만이다.
- 측정하며 만든 세션 24건은 알파 테스트 분석 데이터와 섞이지 않게 측정 후 삭제했다.

## 배운 점 / 재발 방지

- 코드표의 "기타"는 질문 선택지로 쓸 수 없다. 사용자가 답할 수 없고, 데이터에서는 서로 다른 조건을 묶는 상자다.
- "상위 N에서 변별력"은 정렬 규칙에 좌우된다. 정렬이 뒤로 미는 범주(일부 시군구)는 상위 N만 보면 영원히 질문되지 않는다.
- 공공 데이터의 숫자 필드도 단위가 한 가지라고 가정하지 않는다. 소득 상한은 범위를 정해 이상값을 쓰지 않는다.
