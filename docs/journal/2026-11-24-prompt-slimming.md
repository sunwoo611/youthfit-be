# 2026-11-24 선정 사유 프롬프트 경량화 (8주차)

## 상황 / 증상

선정 사유는 정책당 5회가 아니라 후보 상위 5건을 1회 배치 호출로 쓴다(`decisions/011`). 그래도 입력이 세션당 평균 약 1,700토큰이라 입력 컨텍스트를 줄이고 전후를 같은 조건으로 재야 했다. 공공 API 「캐싱」은 일 배치 DB 미러로, 사유 캐시는 세션 JSONB로 이미 충족해서 별도 캐시 레이어는 만들지 않았다.

## 원인 분석

`policies` 4,000건 중 프롬프트에 넣는 원문 필드의 분포(2026-11-24):

| 필드 | 비어 있음 | 중앙값 | 평균 | 250자 초과 | 400자 초과 |
|---|---:|---:|---:|---:|---:|
| 정책 설명 `description` | 0 | 56 | 63 | 42 | 17 |
| 지원 내용 `support_content` | 13 | 104 | 145 | 614 | 207 |
| 추가 자격 `extra_qualification` | 2,735 | 0 | 29 | 115 | 54 |
| 제외 대상 `exclusion` | 3,290 | 0 | 20 | 93 | 42 |

- 기존 상한은 필드마다 400자였다. 길어서 잘리는 쪽은 지원 내용뿐이고, 설명·추가 자격·제외 대상은 400자가 거의 의미 없었다.
- 설명과 지원 내용의 앞부분이 겹치는 정책이 442건(11%)이다. 같은 말이 두 번 들어간다.
- 추가 자격·제외 대상은 사유가 아니라 확인할 조건(`CHECK_POINT_MAX_CHARS`=100자)으로만 옮겨지므로 400자를 줄 이유가 없다.
- 특화 대상이 없으면 `"특화 대상": "없음"`이 모든 정책에 들어갔다.
- JSON을 `", "`·`": "` 공백으로 직렬화했다.

## 해결

`app/services/recommendation_service.py`

- 필드별 상한: 지원 내용 300자(`SUPPORT_MAX_CHARS`), 설명 200자(`DESCRIPTION_MAX_CHARS`), 추가 자격·제외 대상 200자(`CONDITION_TEXT_MAX_CHARS`). 기존 단일 `POLICY_TEXT_MAX_CHARS`(400)는 없앴다.
- 설명이 지원 내용 안에 들어 있거나 앞 30자가 같으면 설명을 뺀다(`_description`). 설명이 지원 내용을 포함하는 더 긴 글이면 정보를 잃지 않도록 남긴다.
- 특화 대상이 없으면 키 자체를 뺀다.
- `json.dumps(..., separators=(",", ":"))`로 압축.
- 시스템 프롬프트 군더더기 정리(역할 문구·"웹사이트 주소"·"지원" 등). 동작·검증 규칙(DB 사실만, URL·날짜 금지, 확인 가능한 자격 4종, check_points)은 그대로.
- 환각 검증(`merge_reasons`의 URL 제거·날짜 검사·plcy_no 대조)과 템플릿 폴백은 건드리지 않았다.

측정 도구: `scripts/measure_reason_prompt.py` (`uv run python -m scripts.measure_reason_prompt 3`). A~D 조건으로 세션을 만들고 실제 LLM을 호출해 입력·출력 토큰·지연·프롬프트 길이·템플릿 대체 수를 사용자별 중앙값으로 낸다. 측정 세션은 삭제한다.

## 배운 점 / 재발 방지

- 입력 토큰은 줄었지만 **지연은 줄지 않았다**. 지연은 출력 토큰(약 490)에 지배되고, 입력 -10%는 호출 간 편차(3.4~4.3초)보다 작다. 성공 기준 중 "입력 토큰 감소"만 달성했고 "첫 요청 지연 감소"는 달성하지 못했다.
- 입력을 더 줄여도 효과가 작다. 지연을 줄이려면 출력(사유 200자·확인할 조건 3×100자)을 줄이거나 정책 수를 줄이는 쪽이 맞다. 다만 이는 사용자에게 보이는 문구 품질과 맞바꾸는 결정이라 ADR로 따로 다룬다(결정 기록: `decisions/015`).
- 경량화 전후는 같은 스크립트·조건으로 잰다. 11-15 실측(답 제출 포함)과 섞으면 비교가 안 된다.
- 템플릿 대체율 0%, URL·날짜 검증 회귀는 없음. 사유 문구의 사실 오류 표본 재검증은 하지 않았다(상한을 줄였으므로 알파 테스트 전에 표본 점검 권장).
