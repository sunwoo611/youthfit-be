# 산학캡스톤디자인 프로젝트 계획서 (정리본)

> 원본: `originals/project-plan.pdf` (git 미포함). 2026학년도 2학기 산학캡스톤디자인.
> 개인정보(이름·학번)는 제외하고 역할로만 표기했다. 구현 기준 문서이며, 발표자료와 다른 부분은 [ADR 001](../decisions/001-stack-and-mvp-scope.md)을 따른다.

- 프로젝트명: 청핏(YouthFit) (가칭, 청픽(YouthPick) 후보)
- 부제: LLM 기반 역질문 대화로 완성하는 청년 정책·금융상품 통합 추천 서비스
- 팀: 2인 (팀장: 프론트엔드·UI/UX / 팀원: 백엔드·데이터·AI)

## 1. 목적 및 필요성

### 문제의식

- 청년층(대학생, 취준생, 사회초년생)의 정책 지원금·우대 적금 수요는 높지만, 신청까지 가는 과정에서 **탐색 병목**이 발생한다.
- 혜택 존재 자체를 모르거나, 복잡한 자격 요건 때문에 기한을 놓치거나 포기하는 **정보 격차 기반 복지 사각지대**가 존재한다.

### 기존 플랫폼의 한계

| 한계 | 내용 |
|------|------|
| 수동 필터링 UI | 온통청년·청년몽땅정보통 등은 나이, 거주지, 학력, 취업상태, 소득분위 등 수십 개 필터를 직접 선택해야 함. 청년 대다수는 기준 중위소득 분위나 고용보험 이력별 구직 상태를 정확히 모름 |
| 정책·금융 사일로 | 단기 지원(월세, 구직수당)과 중장기 자산 형성(청년도약계좌, 우대 적금)이 공공 포털과 민간 금융 플랫폼(금융상품한눈에, 핀다, 뱅크샐러드)으로 분리 |
| 챗봇의 환각·입력 피로 | 긴 줄글 입력 부담, 최신 정책 정보 왜곡, 마감일·공식 신청 URL 미제공 |

- 기존 흐름: 수십 개 조건 인지 → 체크박스/드롭다운 필터 → 단일 도메인 결과 → 자격 여부 직접 검토
- 제안 흐름: "나한테 맞는 적금/지원금 알려줘" → LLM이 핵심 조건 3~5개 역질문(선택형 UI) → 정책+금융 통합 추천(근거/원문 링크)

### 필요성

1. **인지 부하·탐색 비용 절감**: 온통청년 기준 수천 건 정책 + 금감원 공시 수백 건 금융상품. 백엔드가 1차 필터링 후 "당락을 가르는 최소 질문(3~5개)"만 역으로 제시하는 **능동형 인터페이스(Active Querying)** 필요.
2. **수혜율 증대**: 온통청년 Open API + 금감원 금융상품조회 API를 연계해 한 화면에서 원스톱 확인.
3. **기술적 가치**
   - RAG 기반 환각 제거: 공공 API 데이터를 메타데이터 인덱스(및 Vector DB)와 결합해 자격 매칭 근거와 공식 링크를 구조화해 제공
   - 비용 통제: 공공 API 캐싱 계층 + 규칙 기반 1차 필터 + **엔트로피 기반 적응형 역질문 트리**로 LLM 토큰 비용 최소화

### 기존 서비스 비교

| 항목 | 공공 정책 포털 | 민간 금융/추천 | 본 과제 |
|------|----------------|----------------|---------|
| 탐색 방식 | 다중 필터 수동 체크 | 키워드 검색·폼 입력 | 자연어 1문장 + 능동형 역질문 |
| 추천 영역 | 청년 정책 한정 | 금융상품 한정 | 정책 지원금 + 고우대금리 적금 동시 |
| 입력 UI | 체크박스/드롭다운 | 텍스트 입력창·정형 폼 | 3~5회 터치 동적 선택형 칩 |
| 결과 신뢰도 | 단순 목록 (자가 판독) | 상품 스펙 나열 | 선정 사유(자격 매칭 근거) + 공식 URL 필수 |
| 기술 | RDBMS 속성 일치 검색 | 룰 기반 필터링 | 공공 API 메타데이터 필터링 + LLM 추론(RAG) |

### 핵심 달성 목표

1. 단일 자연어 질의로 진입장벽 최소화
2. 능동형 되묻기(Active Prompting): 칩 UI 3~5회 선택으로 자격 요건 특정
3. 통합형 혜택 패키지: 정부/지자체 지원금 + 우대금리 적금 조합
4. 신뢰성 있는 매칭 근거: 자격 충족 사유 + 공식 접수처 원문 링크로 환각 차단

## 2. 수행 방법

### 4단계 하이브리드 파이프라인

1. **자연어 입력·의도 분석** (FE & BE): 예) "서울 사는 취준생인데 지원금이랑 적금 추천해줘" → FastAPI가 거주 지역, 취업 상태, 관심 분야(주거/일자리/금융) 1차 키워드 추출
2. **1차 후보군 추출·메타데이터 필터링** (Data Layer): 로컬 DB에서 정책 30~50건, 적금 10~20건 선별. 외부 API 실시간 호출 없이 사전 캐시된 RDBMS/Vector DB 조회
3. **적응형 역질문 생성** (Active Querying Engine): 후보군 간 수혜 여부를 가르는 핵심 자격 변수(소득 분위, 고용보험 가입 여부, 세부 연령 등) 식별 → LLM이 질문 3~5개 + 선택지를 JSON으로 생성 → FE가 칩 UI로 렌더링
4. **최종 매칭·근거 제공** (RAG Layer): 답변으로 최종 후보 확정 → LLM이 검증된 메타데이터 기반 선정 이유 + 공식 신청 URL을 패키지로 출력

### 계층별 역할

| 계층 | 구성 요소 | 기술 |
|------|-----------|------|
| Frontend | 자연어 입력창, 동적 칩 UI, 결과 카드 뷰 | Next.js, React, Tailwind CSS, 모바일 반응형, 지원금+적금 통합 카드 |
| Backend | API 라우팅·세션 관리, 1차 룰 필터, 캐싱 계층 | FastAPI 비동기 REST, 세션별 질문-답변 상태 추적, 로컬 DB·캐시 |
| AI/LLM | 역질문 생성기, 근거 서술 엔진, 환각 방지 제약 모듈 | GPT-4o-mini 등 프롬프트 엔지니어링, 엔트로피 기반 질문 추출, 자격 근거·공식 URL 1:1 바인딩 |
| Data | 정책 수집, 금융상품 수집, 통합 메타데이터 저장소 | 온통청년 Open API 배치, 금감원 금융상품한눈에 API(정기예·적금), PostgreSQL(비정형 자격 요건 정규화·인덱싱) |

### 기술적 방향성

- **Frictionless UX**: 한 문장 + 3~5회 칩 터치로 1~2분 내 추천
- **Efficiency**: 단순 검색은 SQL 메타데이터, LLM은 질문 도출·근거 생성에만
- **Trust & Actionable**: 검증된 공공 DB 메타데이터와 공식 URL만 제공

### 역할 분담

| 구분 | 담당 | 세부 업무 | 산출물 |
|------|------|-----------|--------|
| 백엔드·데이터·AI | 팀원 | 온통청년·금감원 API 연동 및 일일 배치 수집, 자격 요건(연령·소득·지역) 정규화·PostgreSQL 설계, 1차 룰 필터 엔진, LLM 역질문·RAG 근거 매칭, FastAPI REST·캐싱·배포 | 정규화 DB, 역질문·RAG 파이프라인, REST API 서버 |
| 프론트엔드·UI/UX | 팀장 | Next.js 반응형 웹, 자연어 입력창·대화형 전환, 동적 칩 UI, 통합 카드 뷰(근거·외부 링크), 세션 상태·API 연동, Vercel 배포 | 웹 클라이언트, 칩 UI 컴포넌트, 배포 URL |

## 4. 위험 요소 및 대응

1. **공공 API 호출 제한·지연**: 실시간 조회 대신 일 1회 배치로 로컬 RDBMS에 미러링 → 외부 상태와 무관한 무중단 서비스
2. **LLM 환각으로 허위 자격 정보**: 프롬프트 통제 + DB에 정규화된 실제 모집 요강 메타데이터와 공식 URL만 결합하는 **제약 기반 생성(Constrained Generation)**
3. **비정형 정책 텍스트 정규화 예외**: MVP는 서울·경기 핵심 정책 50~100건 + 금감원 공시 적금에 집중해 규칙 완성 후 전국 확대

## 구현 시 해석 메모

- 계획서의 "RDBMS/Vector DB"는 MVP에서 PostgreSQL만 사용하고, 필요 시 pgvector로 확장한다 ([ADR 001](../decisions/001-stack-and-mvp-scope.md)).
- "엔트로피/정보 이득 기반 질문 추출"은 4주차 역질문 설계 시 구체화한다. 후보군을 가장 고르게 가르는 자격 변수를 SQL로 먼저 계산하고, LLM은 그 변수를 자연스러운 질문·선택지로 표현하는 역할로 한정하는 방향을 검토한다.
